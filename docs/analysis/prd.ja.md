# 分析のプロダクト要件

## 目的

分析は探索で得た証拠を、順位づけ・分類された成果物候補に変換する。証拠の収集と解釈を分離し、探索アダプターがリポジトリ情報の取得に集中できるようにする。

## プロダクトの方針

探索で得た証拠は候補を裏付ける情報として扱い、意味的な関係の証明とはみなさない。証拠を確認できる状態に保ち、候補を確定した関係として示さない。証拠と不確実性に関する全体方針は[プロダクトPRD](../prd.ja.md)を参照。

候補の準備と表示は[フィルター](../filter/prd.ja.md)と[出力](../output.ja.md)を参照。

## 現在の実装

`discoverWithLister` が `PathLister` から証拠を取得し、`analyzeCandidates` を呼ぶ。現行実装は、リポジトリ相対パス、対象と同時に変更されたコミットの集合、コミットメッセージから得たノイズ情報を持つ `cochangeEvidence` を受け取る。`analyzeCandidates` は各証拠から候補を作る。

スコアは共変更コミット数とファイル名の類似ボーナスの合計である。ノイズスコアは別に管理する。コミットメッセージのシグナルは小さく加点し、benchmark/performance系パスなどの内蔵ルールは大きく加点する。既定のノイズしきい値を超える候補は隠し、`--show-noisy` で含められる。`--max-noise-score` でしきい値を変えられる。ノイズルールは利用者のinclude/excludeフィルターとは独立して追加できる。

これらはGit由来の証拠に対するヒューリスティックである。現在の実装はソースの意味解析やLLMを利用しない。

## 今後の方向性

分析により豊富な証拠を取り入れる場合も、証拠を確認できる状態と不確実性を保つ。証拠の種類や手法は未決定である。
