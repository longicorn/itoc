# ADR: 証拠に基づく候補の分析

## 状態

現在の方針。ヒューリスティックとその評価は今後変更する余地がある。

## 背景

分析は、発見した証拠から順位付け・分類された候補を作る。証拠の収集と解釈は別の責務であり、発見アダプターがリポジトリの事実を取得し、分析が確認用の候補を準備する。共変更やパスの一致は候補を裏付ける証拠だが、意味上の関係を確定するものではない。[分析PRD](prd.ja.md)も参照。

## 決定

- 入力された証拠レコードごとに候補を作り、パス、コミット、証拠、発見元、ノイズ情報を保持する。現在のインターフェースはGitと文書による発見で共通に使う。
- 異なる共変更コミットの数にパス類似度ボーナスを加えて候補をスコア付けする。ボーナスはリポジトリ相対パスのトークンを重み付きで比較し、ディレクトリよりファイル名に高い重みを与える。値は0から3で、スコアの内訳が分かるよう別に提示する。
- 拡張子で文書を分類し、ディレクトリや言語ごとのファイル名の慣例からテストらしいパスを判定する。これらは簡易的な推定であり、意味に基づく分類ではない。
- ノイズは候補の関連度と別に扱う。発見処理は、Gitのコミットメッセージの語やパスの規則など、利用可能なシグナルからノイズの証拠を計算する。候補のフィルターは既定で設定可能なしきい値を超える候補を隠し、利用者はノイズの多い候補も表示できる。確認できるようノイズの語とスコアを保持する。これは現在の実装を記録したもので、ノイズによるフィルターを保留していた[全体ADR](../adr.ja.md)の以前のGit中心の方針に代わる。
- 候補の絞り込みと表示はそれぞれの段階に委ねる。分析は利用者がどの候補を採用すべきかを確定しない。

## 結果

確認しやすい単純なシグナルから再現可能な候補を得られる一方、共変更は偶然の場合があり、パスの類似度は関連ファイルを見逃したり無関係なファイルを上位に置いたりする。テストや文書の分類も誤ることがある。ノイズのフィルターで関連候補が隠れる可能性があるため、利用者はフィルターを外した結果も確認できる必要がある。スコアはヒューリスティックであり、確率や証明として扱わない。現在の分析はソースの意味を調べず、LLMも使わない。

## 未決事項

- 関連候補の見落としや確認作業の負担を含め、順位付けとノイズの規則を具体例でどう評価するか。
- どのような証拠を追加し、その寄与と限界をどう示すか。
- 証拠の異なる発見元に対して、スコア付けと分類をどう発展させるか。
