# ADR: Gitによる関連探索

## 状態

採用済み。

## 背景

[PRD](prd.ja.md)は、関連する可能性のある成果物を見つけるため、確認可能なGitの証拠を求めている。共変更は手がかりであり、意味的な関係の証明ではない。一括変更や同じコミット内の無関係な作業によって、誤解を招く候補が生じることもある。関連性は利用者が判断する。

## 決定

追跡対象のリポジトリ内パスに影響したコミットから候補を探索する。削除済みパスの入力は既定では拒否する。`--allow-deleted`を指定すると、履歴に存在するパスをGit履歴から探索できる。対象を移動または改名した場合は現在の移動先から履歴をたどる。共変更を関係の確定として扱わず、根拠となるコミットIDとノイズの証拠を分析用に保持する。

リポジトリルートと、リポジトリからの相対パスとしての追跡対象を解決し、`git log --follow` でコミットIDを取得する。各コミットの件名と本文、および `git diff-tree --root --no-commit-id --name-only -r` が返す変更パスを収集する。対応するコードと文書のパスを候補とし、対象自身を除外する。同じパスは1コミットにつき1回だけ数える。パスごとに証拠を集約し、コミットID、共変更の証拠、メッセージとパスから検出したノイズ語を保持する。ノイズのスコア付けと候補の解釈は[分析](../../analysis/prd.ja.md)に記載する。

Gitの実行処理は差し替え可能で、既定では `git` コマンドを実行する。リポジトリ、対象、ログの取得に失敗した場合は探索を失敗とする。メッセージの取得に失敗したコミットはメッセージの証拠なしで処理し、diff-treeに失敗したコミットはスキップする。このため証拠が不完全になる場合がある。

## 影響と制約

結果は履歴と対応パス種別に依存する。共変更には無関係なものが含まれ、関連ファイルが同じコミットで変更されたことがない場合もある。`--follow` は対象の履歴をたどるが、除外時には変更パスを現在の対象パスと比較するため、過去の名前が候補に現れることがある。アダプターは差分、作成者、時系列、ブランチ、プルリクエスト、作業項目の情報を証拠として収集しない。

既定では対象が作業ツリーに存在することを確認する。`--allow-deleted`指定時は、存在しないパスをGit履歴から解決できる。スコア付けと分類は探索とは別に行う。
