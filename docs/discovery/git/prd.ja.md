# Gitによる関連探索の製品要件

## 目的

リポジトリのパスに関連する成果物の候補を、確認可能なGit履歴から探せるようにする。共変更は関連の可能性を示す証拠であり、意味的な関係の証明ではない。候補が目的に適しているかは利用者が判断する。

## 製品の方向性

対象に影響したコミットを使い、同時に変更された対応済みのコードや文書のパスを候補として特定する。後段の分析と分類のため、根拠となるコミットとコミットメッセージ由来のノイズ情報を保持する。対象自身を除外し、同じコミット内のパスは一度だけ数える。

過去のパスを入力として現在の移動先候補を探せる。履歴追跡は任意で、既定では無効とする。
`--allow-deleted`を指定すると、移動先探索の代わりに、履歴に存在するパスをGit履歴から探索できる。

## 現行実装

Gitアダプターはリポジトリルートと追跡対象のリポジトリ相対パスを解決し、通常は現在のパス、`--follow`指定時は名前変更も含む履歴をたどってコミットメッセージと変更パスを収集する。Gitコマンドの実行処理は差し替え可能で、既定では `git` を実行する。スコア付けと分類は[分析](../../analysis/prd.ja.md)が行う。

## 評価と今後の手がかり

Git履歴には、一括整形、依存関係の更新、リファクタリングなど、関連性を示さない共変更が含まれる。利用者が候補やノイズの判断を確認できるよう、証拠を保持する。[製品PRD](../../prd.ja.md)では、繰り返される共変更、差分、作者や時系列の傾向、作業項目の情報を手がかりの候補として挙げている。ブランチ、プルリクエスト、マージの情報も役立つ可能性がある。これらの手がかりは現行実装には含まれず、特定の手法を採用する約束でもない。

## 移動先と履歴の方針

通常の探索は名前変更を追わず、現在のパスの履歴を調べる。存在しない過去のパスに対しては、パスやファイル名、内容の完全一致、Ctagsの定義情報など利用できる手掛かりから、分割先を含む現在の候補を探す。手掛かりは証拠であり確定ではない。一致がなくても削除されたとは断定しない。明示的な`--follow`モードではGitの名前変更追跡を使う。手掛かりは確認できる形で残し、Ctagsがない場合は警告する。tree-sitterは将来評価する選択肢であり、速度向上を保証しない。
