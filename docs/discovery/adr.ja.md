# ADR: 探索の境界と処理の組み合わせ

## 状態

証拠の収集と分析の分離は採用済み。共通の証拠モデルと実験的なテスト探索は引き続き評価する。

## 背景

[探索のPRD](prd.ja.md)は、個別に選択できる探索方式と、関連パス候補の根拠を確認できることを求めている。証拠は手掛かりであり、意味上の関係の証明ではない。[分析のPRD](../analysis/prd.ja.md)は解釈、スコア付け、分類を分析の責務とし、探索アダプターが証拠の収集に集中できるようにする。方式ごとの判断は[GitのADR](git/adr.ja.md)と[CtagsのADR](ctags/adr.ja.md)に記録する。

## 決定

各主要探索方式は共通の境界を実装する。入力を受け取り、証拠と分析に渡す解決済みの対象、またはエラーを返す。収集が成功したら、分析がその方式の証拠を候補に変換する。証拠とその取得元の方式は確認できる形で保持し、候補の関連性は利用者が判断する。スコア付けと分類の規則は分析の責務とする。

方式はregistryから名前で選択し、`all`は登録済みの方式をすべて選ぶ。重複指定は除き、未知の名前や空の名前はエラーとする。複数方式を選んだ場合は並行して実行し、それぞれの結果を分析してからリポジトリ相対パスごとに候補を統合する。統合時には証拠と方式名を保持する。暫定的な一致ボーナスとスコアの扱いはヒューリスティックであり、確率として較正された値ではない。

複数方式の実行では、選択した方式が失敗すると方式名を含むエラーを返す。ただし、文書形式が未対応の場合はdocument方式をスキップする。document方式だけの実行では未対応形式をエラーとする。証拠の一部が取得できない場合の扱いはアダプターごとに異なり、その制約は各ADRに記載する。

主要な探索結果の統合後、設定に応じて実装候補から一段階だけテスト候補を探索する。派生した証拠はパスごとに統合し、独立方式の一致ボーナスは加算しない。新しいテスト候補のスコアは0とし、既存候補のスコアは変えない。その後、フィルターや件数制限を含む候補の準備を行い、結果を出力する。実験的なテスト探索と失敗時の扱いは[CtagsのADR](ctags/adr.ja.md)に記載する。

## 現在のI/Fと未決事項

現在の`PathLister.List`は`[]cochangeEvidence`、対象の文字列、エラーを返し、`discoverWithLister`は成功時に`analyzeCandidates`を呼ぶ。`cochangeEvidence`は名前に反して文書探索でも使われる。これは現在のI/Fの記録であり、Git由来の形を今後すべての方式に共通する証拠モデルと決めたものではない。取得元に依存しない証拠の表現とI/Fは未決である。

暫定的な統合とテスト探索のスコア規則は評価が必要である。方式の追加や処理順序の変更に伴い、証拠の表現、エラー処理、スコア付けを見直す可能性がある。その際も、追加の一致だけで関連性を確定しない。
