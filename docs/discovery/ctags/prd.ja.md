# Ctagsによる関係探索の製品要件

## 目的

実装を起点に、シンボルの確認可能な根拠を使って関連するコードやテストの候補を見つける。成果物間の関係が分からない場合の調査を支援し、候補が作業に関連するかは利用者や呼び出し元が判断する。

## 製品の方向性

Universal Ctagsで抽出した定義を、関連する成果物を探す手掛かりにする。起点の実装、識別子、一致した位置を根拠として残し、利用者が確認できるようにする。コメントを含む文字列の出現は、参照先の解決、呼び出し、テストによる検証の証明ではない。同名の識別子、言語固有の構文、間接的な関係などによって誤検知や見落としが生じる。一致がないことも関係が存在しない証明にはならない。

将来取得できる場合は、文字列一致、構文上の呼び出し、静的に解決された呼び出しを区別する。到達可能性だけでは機能の範囲は確定しない。テスト以外への探索拡張、対応言語、関係の解決方法は未決であり、現在の実装の要件ではない。

## 現在の試験的な動作

実験的な実装と設計上の選択は[ADR](adr.ja.md)に記録する。

## 評価と未決事項

シンボルの根拠を単独およびファイル名やGitの根拠と組み合わせて評価する。同名、コメント、間接呼び出し、共通テスト、見落とした関係などを含む事例を人手で確認する。ツールの有無とバージョン、対応言語、失敗、根拠、見落とし、無関係な候補、実行時間を記録する。[検証計画](../../discovery-evaluation.ja.md)に比較方法と初期の実現可能性確認を記載する。対象範囲、順位付け、既定値は文字列一致だけで関係を確定せず、評価結果に基づいて決める。
