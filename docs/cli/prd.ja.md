# CLI プロダクト要件

## 目的

CLIは、リポジトリ内の成果物間の関係を探索するためのコマンドラインの入口である。探索、候補の準備、出力を一連の処理として実行し、利用者が候補とその根拠を確認できるようにする。

## 要件

- 探索の起点としてリポジトリ内のファイルパスを受け取る。
- 利用可能な探索方式を選択し、候補の絞り込み、ノイズのしきい値、表示件数を調整できるようにする。
- 候補をテキストまたはJSONで表示し、要求に応じて詳細な根拠を示す。候補は手がかりであり、関係の証明ではない。
- 不正な入力や処理中のエラーを利用者に伝え、失敗を示す終了ステータスを返す。

CLIは処理をまとめる。[探索](../discovery/prd.ja.md)が候補を取得・分析し、[フィルター](../filter/prd.ja.md)が候補を整え、[出力](../output/prd.ja.md)が結果を表示する。対応するオプションと使用例は[README](../../README.ja.md)に記載する。

## 現在の動作

実行ファイルはリポジトリ内のファイルパスを1つ受け取る。出力形式、0以上のスコアしきい値、グループごとの0以上の表示件数を検証する。includeとexcludeのフラグは繰り返し指定できる。

`--discovery`には方式名、カンマ区切りの複数の方式名、または`all`を指定できる。既定値は`git`である。選択した方式を並行して実行し、同じ候補を見つけた方式が増えるごとに、暫定的に1点を加算する。文書探索はMarkdown/MDXとreStructuredTextを別々の抽出処理で扱う。

ノイズルールは既定のしきい値を超える候補を隠す。`--show-noisy`または`--max-noise-score`で調整できる。`--verbose`は詳細な根拠を表示する。エラーは標準エラー出力に表示し、失敗を示して終了する。

実験的な`--search`はキーワードから起点となるパスを探す。動作と未決事項は[キーワード検索のPRD](../keyword/prd.ja.md)に記載する。

`--allow-deleted`を指定すると、削除済みの入力をGit履歴から探索できる。削除済みの入力には文書探索を併用できない。
