# キーワード検索のプロダクト要件

## 目的

キーワード検索は、関連するパスが分からない場合に、リポジトリ内の成果物を探し始めるための入口を提供する。機能名や画面に表示される文言を手掛かりに、初めて触れる実装や文書を探すことを想定する。

## 方向性

itocは明示的に指定されたキーワードからリポジトリ内のパス候補を探し、それぞれの一致根拠を示す。人やAIが結果を確認できるよう、何がどこで一致したかを分かるようにする。文字列の一致は手掛かりであり、その成果物が目的の機能を実装または説明している証明ではない。一致がない場合も、関連する成果物が存在しないとは限らない。

検索結果は探索を始めるための候補である。選択したパスから先の関係探索は[discovery](../discovery.ja.md)が担う。どの候補を調査または採用するかは利用者や呼び出し元のワークフローが判断する。キーワード検索自体がassessmentの対象範囲を確定するわけではない。

CLIは `itoc [options] <file-path>` と `itoc [options] --search <keyword>` を案とする。オプションを明示することで、存在しないパスをキーワードと誤解釈することを避ける。CLIは仮の入口として `--search <keyword>` も受け付ける。検索は未実装であることを表示し、discoveryやスコア計算は実行しない。

## 未決事項

- リポジトリ内のどのファイルや箇所を検索し、どの一致根拠を表示するか。
- 複数の開始候補をどう選択し、discoveryに渡すか。
- 一般的な語や曖昧な語を含む一致をどう順位付け・絞り込みするか。重みや順序は評価に基づいて検討する。
- 空の入力、不正な入力、一致がない検索をどう報告するか。

実装手法や `keyword.go` との関係は設計時に決める。具体例と評価を使いながら段階的に検討する。
